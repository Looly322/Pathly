# Pathly 国外页面质量修复实测（2026-10-15）

运行地址：http://localhost:5173/ 。本次未修改国内高德组件、核心规划算法，也未接入 Foursquare、付费翻译或新的付费地图。

## 发现的问题与修复

1. 原前端媒体请求等待 90 秒且重试两次，全局仅两路并发；后端所有 OTM 景点详情共用一把锁。慢图片导致其他景点排队。现为四路有界队列，排队计入 15 秒截止时间，不自动重试；后端按 xid 去重，锁等待有界。原文/官网、译名、图片分开请求，基础行程不等待它们。
2. 原先只缓存有图结果，无图地点不断重查。现在浏览器缓存成功、缺失与短期失败，后端开放媒体缓存缺失 10 分钟；手动重试只针对当前景点。城市切换已有版本校验，卸载后的媒体结果不更新旧页面。
3. 原 Wikidata 通用缓存扫描整个目录，还可能把仅含 claims 的缓存作为含 labels 的响应使用。现用精确 URL 缓存；不同字段查询不会误命中不完整记录。
4. 海外目的地解析等待国内服务失败；餐饮补充还会串行阻塞首屏（开罗基线该请求 25.1 秒超时）。现目的地解析并行，餐饮补充独立进行，12 秒结束；新增餐饮到达后提示重新生成，不覆盖用户已编辑行程。
5. 图片实际请求出现 `net::ERR_BLOCKED_BY_ORB`：原代码把 Commons 已返回地址覆盖成 OTM 的旧缩略图地址。现保留 Commons 当前地址和作者/授权。检查中还修正了懒加载图片完成后被超时计时器错误替换的问题。图像加载超时才回退，离屏图片不提前计时。
6. 原详情英文大段直接输出。现在使用 xid 的 Wikidata 关联补充中文标签/简短介绍，中文缺失则明确标记来源原文；英文界面也对非英文原文提示。默认四行，支持展开。没有声称提供全文机器翻译。
7. 国外原 Leaflet 桥接 Positron 底图偏灰。已实测 Bright、Liberty 后选用原生 MapLibre GL JS + 官方 OpenFreeMap Liberty，保留官方道路层级、公园水域建筑与设施层；无整体去色。中英文通过修改矢量图层 text-field 即时切换，不重建地图。编号圆点、选中弹窗、列表双向联动、缩放拖动和路线均保留。虚线明确为直线顺序示意，不是道路导航。

## 实际加载耗时

点击生成到结果页出现，三天行程；自动浏览器真实运行。各次缓存和网络状态不同，**不是严格冷缓存 A/B 实验，也不能保证所有城市低于一秒**。

| 城市 | 修改前 | 最终复测 | 15 秒观察时已加载图片 | 持续加载提示 |
|---|---:|---:|---:|---:|
| 巴黎 | 13.275 秒 | 0.289 秒 | 2 / 4 | 0 |
| 东京 | 地名请求 60 秒超时，未生成 | 0.253 秒 | 3 / 4 | 0 |
| 开罗 | 26.834 秒 | 0.258 秒 | 4 / 4 | 0 |
| 北京 | 1.867 秒 | 1.426 秒 | 4 / 4 | 0 |

最终海外地点查询命中后端缓存约 20–23 毫秒，目的地约 37–43 毫秒。较早一轮东京地点查询实际等待 6.503 秒，总生成 7.066 秒。餐饮补充巴黎、东京仍在 12 秒超时，但不影响结果页。

图片采用懒加载，15 秒计数包含尚未滚动进入视野的图片，不能简单当作缺图率。巴黎单独滚动复测 4/4 图片实际加载成功（naturalWidth 均为 500），包括此前失败的巴黎圣母院和 Louis XIII。单独图片诊断见 `quality/photo-diagnostic.json`，滚动后截图 `quality/paris-images-verified.png`。媒体请求的 HTTP 成功不等于图片实际成功，诊断另外记录浏览器图片状态与 naturalWidth。

首日中文标题：北京 4/4；巴黎 1/4（巴黎圣母院）；东京 1/4（新宿尼亚加拉瀑布）；开罗 0/4。其余保留来源名称。巴黎圣母院有可靠中文短介绍，其他缺失项展示原文提示和折叠。未杜撰中文译名。

`quality/final.json` 的巴黎 0 项记录受到开发热更新重载影响，作废；完整稳定复测以 `quality/verified.json` 为准。保留原记录以便复核。

## 地图验收

巴黎、东京、开罗使用生产 GlobalMap 组件和真实免费瓦片；北京使用原高德。四城均通过：加载、中心/景点位置、编号、点击、选中高亮、列表联动、语言切换后中心/缩放保持、路线绘制与缩放拖动。实际截图保存在 `quality/map-*.png`。

Bright 样式的真实命名要素抽样（城市级视野，非全城市覆盖率）：巴黎中文字段 38/52、东京 16/112、开罗 4/66；英文抽样分别 46/46、98/98、60/60。Liberty 与其共享底层数据，中文街道缺失仍会保留当地文字。不能保证全中文，英文字段也可能包含源数据音译或错误。

官方说明：https://openfreemap.org/quick_start/ 。现有依赖已包含 MapLibre，没有新增地图依赖、Key 或收费服务。公共服务网络可用性不由 Pathly 保证。

## 修改文件

前端请求与流程：
- `src/services/placePresentation.js`：队列、超时、去重、分通道和正负缓存。
- `src/providers/destinationResolver.js`：地名查询并行和内存去重。
- `src/providers/placeProvider.js`、`src/App.vue`：餐饮异步补充与旧请求校验。
- `src/views/TripResultView.vue`：独立媒体状态、按地点重试、合并结果、补充候选提示。
- `src/components/ActivityImage.vue`：懒加载、加载时限和安全占位。
- `src/components/PlaceDescription.vue`（新增）：语言选择、原文提示、折叠展开。
- `src/components/GlobalMap.vue`：原生 MapLibre、编号与路线、交互和语言同步。
- `src/utils/mapStyle.js`：Liberty 与多语言字段回退，移除去色/压制图层修改。

后端：
- `backend/global_places.py`：精确缓存、主机锁超时、媒体任务预算。
- `backend/opentripmap.py`：分通道详情、有限锁等待、译名与图片来源修复。
- `backend/place_media.py`：缺失结果缓存，文字查询不请求照片。
- `backend/server.py`：part 参数和媒体任务截止时间。

测试：
- `tests/presentation.test.js`、`tests/mapStyle.test.js`、`backend/test_place_media.py`。
- `tests/browser/core.spec.js`、`tests/browser/maps.spec.js`、`tests/browser/quality.spec.js`（新增）。
- `tests/live/quality-profile.mjs`、`tests/live/photo-diagnostic.mjs`（新增）、`tests/live/world-map-candidate.mjs`。

## 验证结果与限制

- 前端单元测试 52/52，后端 19/19，浏览器 14/14。
- 浏览器包括原有多日规划/编辑/游客评价，真实四城地图，以及故意延迟媒体、破图、加载后计时器、快速切换日期与语言的异常测试。隔离功能测试采用明确的测试夹具；真实 API 实测另见报告，未把夹具当真实服务结果。
- `npm run dev` 实际运行；`npm run build` 成功。MapLibre 异步包约 1.05 MB（gzip 286 KB），Vite 仍提示大包警告，未伪称首载成本消失。
- 缺少中文名称/介绍的问题仅实现可靠补充与明确回退，数据覆盖仍不足；无免费可靠的全量翻译保证。
- 图片仍受 Commons 网络、限流及原始关联完整性影响；图片来源关联不等于人工核验所有照片内容。无真实图片保留明确的类别插画，不冒充实拍。
- 冷缓存城市仍可能慢或超时；没有修改景点选择质量算法，不宣称本轮解决小众城市 POI 覆盖不足。
